# Schema Design

## Current Model

- **Slice `status.yml`** (`templates/skills/weave-slices/status-template.yml`) has the fields `version, id, title, status (pending|in_progress|done), owner, repos[], depends_on[], task_summary{total,done,blocked}, created_at, updated_at`. `readSliceStatus` (`src/lib/sliceRollup.ts:363`) rebuilds only these fields, so anything else is dropped on rollup.
- **Change `status.yml`** holds lifecycle state (`stage`, `artifacts`, `stale`, `stress_tests`, `auto_advance`, `runs`, `checkout.repos.<repo>.base_commit`, `next_step`), written through `src/lib/changes.ts`.
- **Weave-only refs** already exist at `refs/weave/remotes/origin/*`.
- **Machine-local state** lives in `<git-common-dir>/weave/`.

## Proposed Model

### Slice `status.yml`: new `review:` block

Only `weave review record`, `weave review skip`, and the rollup out-of-date check write this block.

```yaml
review:
  state: in_review      # stored: in_review | reviewed | reviewed_with_rulings | waiting_on_person
                        # | skipped | review_failed | predates_review
                        # derived only (never stored): not_reviewed, out_of_date overlay
  start_ref: refs/weave/reviews/<change>/<slice>/start      # absent -> fallback to base_commit
  latest_run: r3
  reviewed_task_total: 5          # active task count at review end; a higher count later -> out of date (derived)
  merge_base: { root: <sha> }     # merge-base the end snapshot was taken against
  plan_basis:                     # frontmatter-stripped body hashes; any change -> out of date (plan changed)
    prd.md: <hash>
    architecture/index.md: <hash>
    task-slices/02/slice.md: <hash>
    decisions: { 261108-4ko1: <hash> }
  fingerprint:                    # per repo: path -> git blob hash or "absent"; slice-owned files only,
                                  # excluding wiki/changes/** and foreign files; a file leaves this set
                                  # when a later review covers it (latest review owns a file)
    root:
      src/lib/foo.ts: 3b18e512...
      src/lib/old.ts: absent
  counts: { open_rulings: 1, parked_minors: 2, human_checks: 0, untested_tasks: 0 }
  independent: true               # false when the client ran the review inline
  partial: false
  updated_at: <iso>
```

`not_reviewed` is derived, not stored. A slice that is ready for review (every active task `done` or `not_tested`) and has no review block, or only a `start_ref`, reports `not_reviewed`, unless the change was adopted after the slice was already ready, in which case it was stamped `predates_review` once. Out-of-date is an overlay computed by `effectiveState`. The stored state is kept, so reverting the code makes the slice current again.

### Change `status.yml`: new `review:` block

```yaml
review:
  state: not_started    # not_started | in_progress | ready_to_merge | ready_with_parked_items
                        # | not_ready | skipped   (out of date is a derived overlay)
  adopted_at: <iso>     # first contact by a review-aware CLI; slices ready before this -> predates_review
  latest_run: f1
  skipped: { reason: "docs only", at: <iso> }   # present only when skipped (FR52)
  fingerprint: { <repo>: { <path>: <blob> } }    # union of change-review files
  counts: { open_rulings: 3, parked_items: 4, plan_problems_open: 0 }
  partial: false
  updated_at: <iso>
```

### Readable records

```text
wiki/changes/<id>/task-slices/<slice>/review.md        # one section per run, newest first
wiki/changes/<id>/task-slices/<slice>/review/
  r1.report.md                                         # reviewer response, verbatim
  r1.findings.json                                     # validated findings (immutable kind/severity)
  r1-round1.patch                                      # fix round diff (git apply -R to undo)
  r1-round1.check.md                                   # fix-checker response, verbatim
wiki/changes/<id>/review.md                            # final review runs, verdict, ALL rulings list
wiki/changes/<id>/review/f1.report.md, f1.findings.json, f1-fix.patch, f1-fix.check.md
```

`review.md` is generated by `record` from the JSON files using `review-record-template.md`. Each run section has these parts:

- header: run id, scope, model level, independent, partial, start and end refs
- **Strengths**
- **Findings**: a table of id, severity, kind, location, fails, and status (open, fixed in round N, ruling, parked, waiting on person)
- **Fixes**: finding id, round, patch file, and the files it touched
- **Rulings**: finding id, reasoning, cost if wrong, basis hashes, and whether it is reopened
- **Declined to judge**
- **Saved Minors**, **Untested tasks**, **Human checks** (needs your check)

### Finding record (`*.findings.json`)

```json
{
  "run": "02/r1",
  "scope": { "kind": "slice", "slice": "02" },
  "findings": [{
    "id": "02/r1-F3",
    "severity": "important",
    "kind": "code",
    "location": { "repo": "root", "path": "src/lib/foo.ts", "line": 42 },
    "fails": { "type": "guideline", "ref": ".weave/coding-guidelines.md#errors" },
    "detail": "...", "fix_hint": "...",
    "foreign_file": false,
    "resolution": null
  }],
  "declined": [{ "behavior": "...", "reason": "..." }],
  "verdict": "with_fixes"
}
```

`resolution` is set only by `record --resolve`:

```text
{ as: fixed, round, patch } | { as: ruling, agreed, reason, cost_if_wrong, basis } | { as: parked } | { as: dismissed, by }
```

`agreed: true` means the agent accepted the finding as real but could not fix it, for example because the fix would cross slices or the rounds ran out. A Critical ruling with `agreed: true` forces `not_ready`.

Run ids are scoped by the CLI: `<slice>/r<N>` for slice runs and `change/f<N>` for change runs. Finding ids are `<run>-F<n>`.

`kind` and `severity` never change after the first write.

### Ruling basis

```json
"basis": {
  "code":       { "root:src/lib/foo.ts": "<blob>" },
  "guidelines": { ".weave/coding-guidelines.md": "<hashDocument>" },
  "documents":  { "prd.md": "<hashDocument>", "architecture/index.md": "<hashDocument>" },
  "decisions":  { "261108-4ko1": "<hashDocument of decision file>" }
}
```

### Refs

```text
refs/weave/reviews/<change>/<slice>/start
refs/weave/reviews/<change>/<slice>/<rN>/end
refs/weave/reviews/<change>/<slice>/<rN>/round<N>-start
refs/weave/reviews/<change>/<slice>/<rN>/round<N>-end
refs/weave/reviews/<change>/_change/<run>/{end,fix-start,fix-end}
```

Each ref points to a parentless commit object created by `commit-tree` from a tree written through a temporary `GIT_INDEX_FILE` (`git add -A` respects `.gitignore`). In workspace mode there is one ref set per repo, in that repo's object store.

### Local packages (not committed)

```text
<change folder>/.weave/tmp/reviews/<change>/<run>[-roundN].package.md   (self-ignoring .gitignore)
```

A package holds:

- the commit list (`n/a` for snapshots)
- the diff stat
- the per-repo `git diff -U10` between boundaries, with foreign-file sections labelled
- the context manifest: planning docs with paths, applicable decisions from `applies_to`, guideline files per repo (present or absent), settled rulings, reopened rulings, the slice's task evidence (as claims), untested tasks, and human-check steps

## Migration Strategy

- No backfill. On first contact the change gets `review.adopted_at`, and slices already ready for review are stamped `predates_review`, which passes the gate. Slices that become ready later read as `not_reviewed` until reviewed. Slices started before this ships have no `start_ref`, and `package` falls back to `checkout.repos.<repo>.base_commit`. The package header says "fallback base: change base".
- `readSliceStatus` and the rollup writer must carry `review` through unchanged. Today they drop unknown keys, so this must ship in the same slice as the first `review` write.
- Rollup never writes review state. It carries the block through under the per-change lock, and out-of-date is computed at read time by `effectiveState`.
- Change `status.yml` gains an optional `review` key, and readers ignore it when absent.

## Compatibility

- Old Weave versions reading new files: the slice `review:` key would be dropped by an old rollup. That is acceptable because state can be recomputed from `review/*.findings.json` by `weave review status --repair`.
- The `review` key is not a lane, so `changeStages`, staleness propagation, and `weave change progress` are untouched.
- Projects with the workspace setting `review.enabled: false` never get `review` blocks, except through explicit on-demand runs.

## Validation And Risks

- **Invariants:**
  - `kind` and `severity` are immutable.
  - A finding with `kind: plan` can only be resolved as `dismissed_by_person`, or reset by a new run after a plan change.
  - `state: reviewed` requires zero open findings.
  - `state: reviewed_with_rulings` requires every open finding to have a ruling and no plan finding to be open.
  - `ready_to_merge` requires no open items in any slice or the change run.
  - Verdict derivation is pure and tested over all combinations.
- **Risk:** a large untracked tree, such as build output not in `.gitignore`, bloats snapshots. Mitigation: snapshots honour `.gitignore`, and `package` warns when the diff exceeds a size threshold.
- **Risk:** blob-hash fingerprints flag reviews as out of date after formatting-only edits. This is accepted.
- **Excluded paths:** `wiki/changes/**`, relative to the Weave root, is excluded by pathspec from every diff, patch, and fingerprint, so review records and lifecycle files can never make a review out of date or be reverted by `git apply -R`.
- **Human checks:** a `Human check:` line under a task's `### Verification` in `tasks.md` is the only marker counted in `counts.human_checks`.
